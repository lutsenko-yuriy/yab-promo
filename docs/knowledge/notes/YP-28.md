# YP-28: Night mode for the deck

## Notes

## Debrief summary

### 2026-10-24

Debriefed together with YP-24, YP-26, YP-28 and YP-29, which ran side by side in one session.

**What went well**
- Brief → analytics (no events; ideas handed to YP-5) → plan → verification checklist in place of scenarios (no integration harness) → four phases, each red-first. The contrast test, extended to both themes, caught four unreadable text-on-fill combinations before anyone saw them; a token-only theme plus a no-raw-colours test keeps night mode from drifting.
- Behaviour checked in headless Chrome over CDP (Node's built-in WebSocket, no installs), all slides screenshotted in both themes, light theme pixel-diffed against `main`.
- Overall the four went well.

**What was hard or surprising**
- Switching between four tickets in one session (two PRs waiting for approval, a feature mid-build, a parked ticket unparked by another session) cost Yuriy time and attention: keeping track of what was waiting on him, and waiting while the agent hopped branches, rebased and re-checked.
- The agent claimed the case screenshots were light captures without looking; the decision built on it (dim them) had to be revisited once the night-mode screenshots showed they are dark captures. Look before describing an asset.
- The first browser-check script reported a pass on a page that never reloaded: navigating to the same file with only a new `#hash` does not reload it. Force `Page.reload` in such checks.
- The skill router could not route any skill on this machine (system Python 3.9 has no `tomllib`; no `CLAUDE.local.md` with model-tier mappings), so every skill ran inline from its `SKILL.md`. Run `/calibrate`.
- The 21 October case numbers had no recorded counting method, so the recount could not fully reproduce them.

**What to change**
- `docs/workflows/FEATURE.md`: requests that arrive mid-ticket are ticketed straight away but not started until the current ticket is shipped or waiting on the user; queued trivial tickets go out together on one branch and one PR, with one debrief and one ship. Upstream candidate for the YAB template.
