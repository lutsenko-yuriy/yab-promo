# YP-35: Research: record slide animations for review without piling up videos

## Notes

- 2026-10-26: Scope.
  - Ticket-specific constraints:
    - No new installs; the deck tooling is the Python standard library, and earlier checks drove the system Chrome over CDP with Node's built-in WebSocket (YP-28, YP-33).
    - The repo is public, so anything attached to a PR is public and stays there.
    - Not every session is a background job with `$CLAUDE_JOB_DIR`.
  - Must:
    - A way to record that runs offline from a local clone.
    - A check the agent itself can read: it can't watch a video, but it can read images and text.
    - No pile-up.
  - Should: what to record, and how the human sees it.
  - Could: a `/checkup` sweep.
  - Won't: implementation (follow-up ticket).
- 2026-10-26: Precedent. YP-14 already sent click-through videos (headless Chromium → MP4) to the presenter's phone, and they caught a fade that screenshots missed. The debrief kept videos on request only. The script wasn't kept, and the session log doesn't hold it.
- 2026-10-26: The prototype works with what's on the machine: system Chrome (`--headless=new`), Node 26's built-in WebSocket, and ffmpeg 8.1 (Homebrew).
  - [`Page.startScreencast`](https://github.com/ChromeDevTools/devtools-protocol/blob/master/json/browser_protocol.json) sends a JPEG per repaint, and each frame must be acknowledged with `screencastFrameAck`. Each carries a frame swap `timestamp`.
  - The methods are marked experimental in the protocol.
  - Frames come only on repaints, so the MP4 is built with ffmpeg's concat demuxer, giving each frame the time until the next one.
  - About 34–42 fps at 1280×720. Four steps (6 s) took 9 s end to end.
- 2026-10-26: Sizes.
  - The MP4 is small: 80–90 KB for 2–6 s at CRF 28.
  - The working files are not small: about 21 MB per run (the JPEG frames plus the Chrome profile).
  - So pile-up comes from the intermediates, not from the clips. Delete them right after encoding.
- 2026-10-26: The agent's own check: two tools, both verified on a copy of the deck with `data-id="flow-plan"` removed (the YP-32 bug class).
  - **Frame strip:**
    - ffmpeg `fps=10,tile=3x3` over the 0.9 s after a key press.
    - The broken copy shows "Plan" missing and then fading in. The working deck shows no such fade.
    - The fragment fade on `#/purpose` also shows at half opacity, so the strip resolves motion.
    - About 100–200 KB as a PNG, read with the Read tool.
  - **DOM probe** (no video):
    - reveal.js 6.0.2 marks each element Auto-Animate fades in with `data-auto-animate-target="unmatched"` (or `unmatched-N`).
    - The marker stays until the next transition's `reset()`.
    - After the step, listing those inside `Reveal.getCurrentSlide()` gives `[]` for the working deck and `["Plan splits the work plan Approval by a human"]` for the broken copy.
    - It's text, cheap, and exact for this bug class. It doesn't cover CSS transitions or layout jumps, which the strip does.
- 2026-10-26: Alternatives surveyed.
  - [Playwright `recordVideo`](https://playwright.dev/docs/videos): saved when the context closes, scaled to fit 800×800 by default. It needs npm and its own browser download, a heavy new dependency.
  - [Puppeteer `page.screencast`](https://pptr.dev/api/puppeteer.page.screencast): needs ffmpeg and gives WebM/VP9. Now marked obsolete in favour of `Page.record()`. Also an npm install.
  - Raw CDP screencast: no install, and the earlier CDP checks already use the same connection code.
- 2026-10-26: Showing it to the human.
  - **PR attachment.** [gh v2.99.0+ `--attach`](https://github.blog/changelog/2026-09-01-github-cli-media-in-issues-pull-requests-and-comments) on `gh pr comment` / `pr create` takes MP4/MOV/WebM, up to 10 MB on Free plans, and needs [push access](https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli).
    - The local gh is 2.96.0 (2.103.2 is in Homebrew).
    - Before that, there was no public upload API ([gh-attach](https://github.com/Addono/gh-attach/) worked around it with browser cookies).
    - Uploads live on GitHub and are public for a public repo; the docs say nothing about deleting them.
  - **Sent to the session** (`SendUserFile`): reaches the phone, as YP-14 did, and nothing lands in the repo.
  - **Kept locally:** only useful at the computer.
- 2026-10-26: Decision (Yuriy).
  - Recordings are sent to the session.
  - Every PR touching `deck/src/` or `deck/css/` gets the probe and frame strips, plus an MP4 of only the touched slides.
  - Written up as ADR-0003. Implementation is YP-45.
  - The prototype script is attached to YP-45 as a comment, as a starting point.

## Debrief summary

### 2026-10-26

**What went well**
- Quick and fine for Yuriy, with nothing to add or correct.
- A throwaway prototype on a copy of the deck, with one `data-id` removed on purpose, gave first-hand evidence. Both the probe and the frame strip caught the YP-32 bug class.
- Two decisions were asked once (delivery, when to record), and everything else followed from the constraints.

**What was hard or surprising**
- The YP-14 recording script wasn't kept and couldn't be recovered from the session logs. This time the prototype went onto YP-45 as a comment.
- The clips are tiny; the intermediates are not (about 21 MB per run).
- gh gained `--attach` for PR videos in 2.99, after the ticket was written.

**What to change**
- No workflow changes. The implementation is YP-45.
